# Installing, Building and Testing the Angular Apps

Covers [citizen-portal](../../../src/frontend/citizen-portal) and [staff-portal](../../../src/frontend/staff-portal). Run the commands from the app's folder.

## Use yarn, not npm

Both apps are managed with **yarn 1 (classic)**. `yarn.lock` is the real lockfile, and both Dockerfiles run `yarn install`.

- **Don't run `npm install` or `npm ci` in these folders.** npm rewrites `yarn.lock` whenever one exists, even with `--no-save`. On 2026-10-14 that produced a 6,300-line `yarn.lock` diff in staff-portal. If it happens, restore the file with `git checkout -- yarn.lock`.
- **Ignore `staff-portal/package-lock.json`.** It's a stale leftover, last changed in TCVP-1129, and is missing newer dependencies such as `@ngrx/store-devtools`. `npm ci` fails against it, but that doesn't mean the dependencies are broken.
- **If yarn isn't installed globally,** run it through npx: `npx yarn@1.22.22 <command>`.

## Install

```
npx yarn@1.22.22 install --frozen-lockfile
```

`--frozen-lockfile` installs exactly what `yarn.lock` lists and fails instead of changing it.

**Symptom of a stale `node_modules`:** `ng build` fails with dozens of `NG8001 '<element>' is not a known element` / `NG8002` errors across many unrelated components. The first error is usually a `TS2307: Cannot find module '<package>'`. These errors don't come from your change. Re-run the install above and build again.

## Build and test

| Task | staff-portal | citizen-portal |
|---|---|---|
| Build | `npx ng build` (the default configuration; there is no `development` configuration) | `yarn run build-dev` (runs `setenv.ts` first) |
| Unit tests, single run | `yarn test` (headless Chrome, no watch) | `npx ng test --browsers=ChromeHeadless --watch=false` (`yarn test` watches by default) |
| Run only some specs | add `--include='src/app/shared/pipes/**/*.spec.ts'` (repeatable) | same |

The tests use Karma and Jasmine, so assertions such as `toBeTrue()` are available.

## Generated API clients (`src/app/api`)

`src/app/api` is generated by `openapi-generator` (`typescript-angular`) from the checked-in `src/app/api/swagger.json`. The `api:*` scripts in `package.json` regenerate it by downloading swagger from a running Staff or Citizen API (`localhost:5090` / `localhost:5080`).

A full regeneration needs the API running locally, and it can pull in unrelated changes if the checked-in swagger is stale. For a small model change, it's normal to edit `swagger.json` and the affected `model/*.ts` files by hand, copying what the generator produced for a similar existing property. Recent examples are TCVP-3443 (`occamDisputeCreatedBy`) and TCVP-3480 (`disputeSourceType`). Enum members are PascalCase versions of the values, for example `Unknown: 'UNKNOWN'` and `Citz: 'CITZ'`. New model files must also be exported from `model/models.ts`.
